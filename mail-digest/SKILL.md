# 多邮箱内容汇总分析

把多个邮箱的近期邮件汇总成一份带优先级的中文报告：

```text
读取各邮箱 → 合并去重 → 分类（重要/常规）→ 一句话摘要 → 待办清单（按紧急度排序）
```

## 一、数据来源

### A. QQ 邮箱（qq-mail 连接器，无需配置）
1. `GetMe` 取名下所有别名（aliases）及 `alias_id`；主/次别名可能**共享同一收件箱，必须去重**。
2. 每个别名分别 `ListMessages(dir=inbox)`，取「过去 24 小时」或「最新 15 封」中较新者。
3. 合并全部别名结果并去重（同一封邮件只计一次）。

### B. 阿里企业邮箱（IMAP 脚本，无需连接器）
```bash
python scripts/aliyun-mail-fetch.py --hours 24 --limit 15 --preview 200
```
- 输出：账号、窗口、数量；每封含 时间 / 已读 / 星标 / 附件标记、发件人、主题、正文预览、message-id。
- 脚本已内置按「主题 + 发件人 + 分钟」去重，并在抬头标注合并数量。
- 看某封全文：`python scripts/aliyun-mail-fetch.py --show "<message-id>"`
- 只看未读：加 `--unread-only`；结构化输出：`--format json`；窗口调整：`--hours 72`。
- **脚本报错时不要中断任务**：先跑 `python scripts/aliyun-mail-verify.py` 取诊断结论，在报告中注明「该邮箱本次读取失败」及原因，其余邮箱照常汇总。

## 二、凭据与配置

- QQ 邮箱走连接器，无需任何配置。
- 阿里邮箱凭据放在 `aliyun-mail-cred.json`，两个字段：
  ```json
  { "user": "you@yourdomain.com", "password": "邮箱密码或三方客户端安全密码" }
  ```
  检索顺序：`--user/--pass` → **当前工作目录** → **脚本上一级目录** → 脚本目录 → 环境变量 `ALIYUN_MAIL_USER` / `ALIYUN_MAIL_PASSWORD`。
- ⚠️ **凭据文件不可提交 git、不可放进技能目录**，每位使用者本地各自创建。
- 海外站点加 `--site sg|hk|us|de`（默认 `cn` 为阿里邮箱中国内地站点）。
- 首次接入、找不到设置入口、各类报错排查 → 见 `references/aliyun-mail-setup.md`。

## 三、分类规则

- **重要邮件**：订单 / 账单 / 付款到账 / 发票 / 验证码 / 安全告警（异地登录、绑定变更）/ 服务条款变更 / 产品功能更新 / 会议邀请 / 截止日期 / 商机与订单逾期提醒 / 带附件的重要函件。
- **常规邮件**：推广、订阅、平台营销推送、newsletter。
- 以下**时效性风险必须置顶**并在待办清单中排最前：
  - 发货逾期倒计时（「距逾期仅剩 N 天」）
  - 买家已付预付款待发货、TT 到账需关联线上订单
  - 商机 / 报名类限时截止
  - 账号安全（绑定变更、异地登录、密码相关）

## 四、输出格式（简体中文）

1. **概览**：邮件总数量、覆盖的邮箱账号列表、重要 / 常规占比、明确的数据口径（时间窗口）。
2. **重要邮件清单**：每封写一句话摘要，**标注所属邮箱账号**。
3. **待办提醒清单**：按紧急程度排序，标注截止时间，以及涉及的单号 / 买家 / 金额。
4. 全部邮箱都没有新邮件时，只回一句「今日暂无新邮件」，不硬凑内容。

报告直接输出到对话，默认不写文件；用户明确要求落盘时才生成文件。

## 五、边界

- 只做**读取与分析**；发送、回复、转发、删除等写操作**必须先取得用户确认**。
- 待办里的金额、单号、买家名、日期一律**引用原文**，不推断、不补全、不换算。
- 邮件正文常混有平台营销话术，不要把推广措辞当成业务事实。
- 汇总只覆盖用户自己的邮箱；不主动扩大收取范围。
