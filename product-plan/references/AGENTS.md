# AI 产品策划与出图工作区

本库不是完整业务库。以“一产品一个文件夹”为基本单位，只管理三段生产流程：

```text
product-plan 产品策划 → Codex 内置 imagegen 生图 → ps-batch-image-actions 加 Logo
```

## 产品目录约定

```text
[产品名称]/
├─ 产品状态.md
├─ [产品名称]_无品牌B2B营销方案.md
├─ product-data.json              # 有 1688 来源时
├─ 1688页面截图.png                # 有 1688 来源时
├─ 参考图_01.*
├─ 参考图_02.*
├─ 营销图/
├─ +logo图/
└─ logo_config.json               # 有产品专属规则时
```

- 不创建按状态划分的根目录，不移动产品文件夹。
- 不创建集中式 `artifacts`；过程日志只保留任务所需的最小临时文件。
- 新产品复用同名目录，旧产品只在再次使用时整理。
- `1688_...` 采集缓存和专利/竞品研究目录属于辅助资料，不进入产品看板；使用时再回流到具体产品。
- `product-plan` 的正式方案保存在产品根目录。
- Codex 内置 `imagegen` 每张图单独生成；确认采用后复制回产品的 `营销图`。
- 正式无 Logo 图命名为 `[产品名称]_Image_01` 至 `[产品名称]_Image_06`。
- 加 Logo 从 `营销图` 非递归读取，输出到 `+logo图`，保持完全相同的文件名，不覆盖无 Logo 图。
- 每次用户确认、阶段开始、阶段完成或发现异常后，立即更新 `产品状态.md` 的状态、出图进度、下一步、待确认、问题和最后更新，确保 AI 工作台同步。
- `最后更新` 使用北京时间 `YYYY-MM-DD HH:mm`，每次状态变化都刷新；工作台“已完成”按该字段降序排列，最新完成的产品必须显示在最上方。
- `出图进度` 始终直接写为 `已完成张数/计划总张数`，例如 `0/6`、`3/6`、`6/6`；不得使用“未开始”“进行中”“已完成”等文字替代。

## AI 工作台流转

- 产品方案与六图Prompt完成：`策划待确认`，进入“待确认”。
- 用户确认方案：立即改为 `待生图`，进入“AI生图”。
- 开始生成图片：`生图中`，每确认回流一张正式图就把 `出图进度` 更新为明确的 `几/几`。
- 六张无Logo图完成：`图片待确认`；用户确认采用后改为 `待加Logo`，仍显示在“AI生图”。
- 六张Logo图全部成功：`已完成`。
- 图片重做、Logo处理失败或流程暂停：分别使用 `图片待修改`、`Logo区域异常`、`暂停`，进入“异常需要处理”，并在“问题”和“下一步”写清具体处理动作。
- 工作台不再显示“旧产品待整理”；旧产品只有再次进入实际流程时才整理和更新。

## 状态值

只使用：`待整理`、`待策划`、`策划中`、`策划待确认`、`待生图`、`生图中`、`图片待确认`、`图片待修改`、`待加Logo`、`Logo区域异常`、`已完成`、`暂停`。旧产品新建状态卡时使用 `待整理`，不能根据文件数量自动标记为已完成。
