# 跨境电商产品营销方案生成器

把产品资料转为一套可直接使用、前后一致的无品牌B2B营销方案。

```text
产品事实 → Commercial Strategy Engine → 单一 Buyer Persona → 3个标题/关键词/卖点 → 6图Prompt
```

## 核心原则

1. 只输出一套 Final Strategy，不生成 A/B/C 完整备选方案。
2. 3个标题、关键词、卖点、首图和后续图片必须共同服务于同一 Buyer Persona。
3. 只把来源页面、图片或用户资料明确支持的信息写成事实。
4. 合理推断须逐项标注 `【推断】`；无法可靠判断且影响营销或合规的内容标为 `待确认`。
5. 删除品牌名、商标、Logo、平台名、版权角色、专利暗示及未经授权的对标词，以无品牌方式呈现。
6. 不把来源平台或渠道写成产品属性，如 `Amazon Style` 或 `for Amazon Users`。
7. 中英文内容逐项对应，英文自然、清晰并符合B2B采购语境。对应中文直接放在英文下一行，不在中文前添加“中文释义：”“中文：”等标签。
8. 本工作区所有产品均已由用户确认支持 `OEM` 和 `ODM`。将这两项视为已确认的供应能力，可用于标题、关键词、卖点、采购策略和图片规划；来源页未提及不构成证据缺口。该全局事实不自动证明具体定制项目、贴牌方式、包装、模具、颜色、起订量、打样费或交期，这些细项缺少资料时仍标为 `待确认`。

## 项目目录与保存规则

执行本技能时，以产品的无品牌通用中文名称建立项目目录，并把正式成果保存到：

```text
E:\AI Product\产品库\[产品名称]\
├─ 产品状态.md
├─ [产品名称]_无品牌B2B营销方案.md
├─ 参考图_01.[原扩展名]
├─ 参考图_02.[原扩展名]
├─ product-data.json                 # 使用1688链接时
├─ 1688页面截图.[原扩展名]            # 使用1688链接时
├─ 营销图\
└─ +logo图\
```

- 创建产品目录时同步创建 `营销图` 和 `+logo图` 两个同级文件夹，不自动增加其他一级目录或原始资料子目录。
- 所有产品始终保存在 `E:\AI Product\产品库` 下，不得在 `E:\AI Product` 根目录创建产品文件夹。
- 创建或更新产品目录根部的 `产品状态.md`，供 Obsidian 汇总。完成产品方案后至少写入：`类型: AI产品`、产品名称、`状态: 策划待确认`、`出图进度: 0/6`、下一步、待确认项、问题、当前方案链接和最后更新时间。`最后更新` 使用北京时间 `YYYY-MM-DD HH:mm`，每次状态变化都刷新；“已完成”视图依靠该字段降序排列，最新完成的产品置顶。当前方案使用仓库路径 `[[产品库/产品名称/方案文件名]]`。若状态卡已有人工内容，只更新这些结构化字段，不覆盖正文记录。
- 把本技能生成的完整最终方案写入产品目录第一级的 `[产品名称]_无品牌B2B营销方案.md`，不能只在对话中展示。
- 把用户提供且实际用于分析或生图的参考图片原样复制到产品根目录，按 `参考图_01`、`参考图_02` 等顺序命名并保留原扩展名。
- 输入为1688链接时，先完整执行 `1688-scraper`，再把本次使用的 `product-data.json`、来源页面截图和下载的产品参考图片复制到产品根目录；在方案和JSON中保留原始1688链接与采集时间。不得只保留临时采集目录中的文件。
- 调用 `1688-scraper` 时使用本次任务专属临时目录，不得把 `1688_...` 采集缓存长期留在 `E:\AI Product` 根目录。复制完成后逐项确认产品目录中的 `product-data.json`、`1688页面截图` 和实际使用的参考图均存在、可读且非空；验证成功后删除整个临时采集目录。若复制或验证失败，保留临时目录用于恢复，并在状态卡“问题”中记录原因，不能提前清理。
- 后续使用 Codex 内置 `imagegen` 生图时，每张图单独调用；把确认采用的无Logo图片从 Codex 默认生成位置复制回 `营销图`，不得只留在对话或默认生成目录。使用 `ps-batch-image-actions` 添加真实Logo时，从 `营销图` 非递归读取并把成品保存到 `+logo图`。
- 正式图片按 `[产品名称]_Image_01` 至 `[产品名称]_Image_06` 顺序命名，产品名称必须与项目文件夹一致。加Logo版本保留完全相同的文件名，由独立的 `+logo图` 文件夹区分，不改写 `营销图` 中的无Logo原图。
- 生图过程中同步更新状态卡：开始时为 `生图中`，`出图进度` 按 `1/6` 至 `6/6` 更新；六张正式图片回流后为 `图片待确认`；用户确认后为 `待加Logo`。需要重做时使用 `图片待修改` 并记录具体图片和问题。
- AI工作台必须随流程实时同步：方案和六图Prompt完成后写 `策划待确认`；用户确认方案后立即写 `待生图`；开始生成时写 `生图中`；每张正式图确认回流时更新进度；六张完成写 `图片待确认`；用户确认图片后写 `待加Logo`；全部Logo图成功写 `已完成`。任一步出现图片重做、Logo失败或暂停，分别写 `图片待修改`、`Logo区域异常` 或 `暂停`，并记录具体问题与下一步。不得等整个任务结束才统一更新。`出图进度` 始终使用 `已完成张数/计划总张数` 的明确格式，例如 `0/6`、`3/6`、`6/6`，不能写成描述性文字。
- 工作台分区固定为：`策划待确认`进入“待确认”；`待生图`、`生图中`、`图片待确认`、`待加Logo`进入“AI生图”；`图片待修改`、`Logo区域异常`、`暂停`进入“异常需要处理”；`已完成`进入“已完成”。不再维护或显示“旧产品待整理”分区。
- 若 `产品库` 中同名产品目录已经存在，复用该目录；未经用户明确要求，不覆盖已有方案或图片，使用版本号或新文件名保存。候选或历史版本不得伪装成正式的六张标准文件。

## 1. 获取并整理产品信息

接收产品链接、图片、规格表和用户补充资料。

- 若为 `detail.1688.com` 链接，先使用 `1688-scraper`，读取其 `product-data.json`、截图和产品图片；按该技能处理登录或验证码。
- 以本商品资料为主要证据。同类或竞品资料只能辅助判断，不能补写为本商品事实。
- 提取通用名称、类目、外观、材质、结构、规格、SKU、功能、场景、价格、MOQ、包装和定制能力；动态价格、库存、销量、物流和交期注明采集时间，未可靠读取的字段标为 `待确认`。

将信息分为：

- `已确认`：有明确资料支持。
- `【推断】`：依据外观、类目或同类产品合理判断。
- `待确认`：缺少可靠证据，且会影响标题、图片或合规。
关键待确认项优先向用户说明；若用户要求直接生成，采用保守表达，不虚构精确参数。

## 2. 产品基本信息

输出简洁表格：

| 项目 | 内容 |
|---|---|
| 产品名称与类目 | 无品牌通用名称；类目用 `>` 分层 |
| 材质与结构 | 实际信息及证据状态 |
| 规格与SKU | 尺寸、重量、容量、颜色、款式等 |
| 采购成本与MOQ | 来源人民币单价、价格区间及起批量 |
| 包装与定制 | 写明用户已确认所有产品支持OEM、ODM；具体定制项目与包装细项仅写已确认内容，其余标为待确认 |
| 产品定位 | 经济型、走量款、中端或高端，并说明依据 |
| 证据缺口 | 影响营销或合规的待确认信息 |

### 美元阶梯价格

基本信息表后另起表格。美元单价按 `人民币采购单价 × 倍率 ÷ 6.7` 计算并保留2位小数；每档采用来源页面对应该数量的人民币单价，只有单一价格时三档共用，价格为区间时同步换算区间，不得自行选取或虚构成本。

## 3. Commercial Strategy Engine

先评估可能采购该产品的B2B人群，例如：

- Distributor / Wholesaler；Brand Owner / Private Label Buyer；Retail Chain / E-commerce Seller；Gym / Studio / Club Buyer；School / Institution / Project Buyer；Promotional Gift Buyer；Rental / Hospitality / Commercial Operator

根据产品用途、MOQ、定制能力、价格带、目标市场和证据强度，只选择一个商业匹配度最高的 Buyer Persona。`SEO`、`OEM`、`Premium` 是策略手段或价值表达，不是采购人群。

输出一行选择摘要，包含 Buyer Persona、采购任务、核心痛点、价值主张、搜索意图和选择理由；简要说明其为何优于其他候选，但不为其他人群生成策略包。

再输出精简 Creative Direction Card：

```markdown
### Final Strategy — [English Name] / [中文名]
- Buyer Persona and Procurement Mission:
- Primary Pain Points and Decision Drivers:
- Search Intent, Keyword Cluster and Core Value Proposition:
- Hero Image First Impression:
- Supporting Image Narrative:
- Avoid:
```

## 4. Final Strategy 内容

### B2B标题

生成3个英文标题及各自的对应中文，按推荐优先级排列。三个标题只允许通过关键词顺序、属性重点和采购意图重点形成差异，不得改变产品事实、Buyer Persona 或整套 Final Strategy。

- 每个标题须为100–125个字符；生成后逐个准确校验长度，不合格则重写。
- 使用真实且相关的产品词、属性词、场景词和交易词，匹配所选人群的搜索意图。
- `OEM`、`ODM` 在本工作区已由用户全局确认，可以使用；`Wholesale`、`Bulk`、`Custom`、`Private Label`、`Supplier`、`Manufacturer` 等其他交易或供应词仍仅在对应能力已确认时使用。不得因支持OEM/ODM而推断具体定制范围。
- 不堆砌近义词，不使用无关流量词、品牌词、平台词、未经证实的认证词或不必要标点。
- 每个标题按以下固定格式输出，英文标题、字符数、对应中文各自独占一行，三者必须换行隔开；字符数不得与英文标题写在同一行。对应中文不添加“中文释义：”“中文：”等标签。3个标题后统一输出一句关键词逻辑，无需展示校验代码。

```markdown
#### 标题 1
[English title]
字符数：123
[对应中文]
```

### 5个关键词

输出5个可独立搜索的英文短语，并在每个英文关键词下一行直接给出准确、自然的对应中文，不添加中文标签。至少2个高相关产品词或长尾词，至少1个采购任务词，至少1个材质、功能、场景或交易意图词。避免重复、品牌词、平台词、错误材质和无证据认证词。对应中文用于方案阅读和确认，不替代英文关键词，也不计入关键词数量。

### 6条卖点

输出6条亚马逊风格英文卖点，并在每条英文卖点下一行直接给出对应中文，不添加中文标签。这里的“亚马逊风格”仅指文案结构与可读性，不得在卖点中出现 `Amazon`、平台名或渠道名。每条采用 `简短大写利益点标题 - 完整自然句` 的结构，先给消费者或采购商可感知的利益，再用已确认产品事实支撑；保持简洁、易扫读、不堆砌关键词。

卖点中严禁出现任何价格或规格参数，包括但不限于：

- 价格、币种、成本、折扣、利润、阶梯价、报价；
- MOQ、起订量、订单数量、采购数量或数量门槛；
- 长度、宽度、高度、直径、厚度、重量、容量、尺寸数值、规格代码、型号、SKU 数量或具体规格列表。

价格与规格只保留在产品基本信息、美元阶梯价格、标题、关键词或图片规格规划等对应模块，不得进入6条卖点及其对应中文。

六条内容共同覆盖且互不重复：1. 材质或产品性能；2. 结构与使用手感（不含参数）；3. 使用场景与消费者利益；4. 零售陈列或商品组合价值；5. 已确认的定制或供应能力（不含数量门槛）；6. 风险降低或信任因素。六条始终对应同一 Buyer Persona；证据不足时使用保守表达。

## 5. 六图规划

先输出规划表：

| 图片 | 图片角色 | 采购问题 | 核心信息 | 视觉方向 |
|---|---|---|---|---|
| Image 1 | Hero Image | 这是什么产品 | ... | ... |
| Image 2–6 | 按策略分配 | ... | ... | ... |

Image 2–6 从核心功能、材质结构、尺寸SKU、使用场景、定制、包装交付、商业适配、质量流程、对比选型、采购服务中选择五个最重要且不重复的角色。

### Image 1 首图规则

- 完整清晰展示真实产品，关键部位不得裁切；产品为唯一或绝对主体，占画面约75%–85%。
- 使用白色或极浅中性背景，第一眼能识别产品；允许一条服务于核心定位的必要英文短文案，不得遮挡或削弱产品主体。
- 不以人物、局部特写、复杂场景、工厂、仓库、证书、包装堆或信息图拼贴为主体。
- 不虚构附件、结构、纹理、颜色、包装或Logo；允许符合真实形态的展开、卷起、折叠或组合摆放。
- 根据 Buyer Persona 选择清晰目录型、专业规格型或高价值品牌型摄影语言，但不得牺牲产品识别度。

### Image 2–6 规则

- 每张图回答一个真实采购问题，全套保持产品外观、色彩、材质、灯光、排版和文案语气一致。
- 可按图片任务使用信息图、尺寸线、功能标注、应用场景、包装或信任元素，画面文字保持必要、简短、自然。
- 工厂、证书、检测及具体供应能力只有在有真实资料时呈现，否则改为中性流程或标注需要素材；需要人物时统一使用与真实使用场景匹配的成年欧洲白人模特。

## 6. Prompt规则

为 Image 1–6 各输出：图片名称、Purpose、English Prompt，以及下一行直接对应的中文内容；中文内容前不添加中文标签。

- Prompt保持简洁，依靠内置生图工具理解画面方向，不重复堆砌摄影参数、形容词和通用禁止项。
- **产品形态一致性是最高优先级**（2026-08 麂皮绒瑜伽铺巾案例教训）：图生图模式下，参考图约束权重必须高于文字约束。每张 Prompt 都使用同一组真实产品参考图，并明确保持产品颜色、材质、结构、比例和关键细节一致；不确定项不得写成精确事实。任何文字/构图/风格约束都不得以牺牲产品形态为代价——若发现 AI 把产品画成其他形态（如薄铺巾画成厚瑜伽垫），该图作废重做。
- **验证过的文案+安全区平衡写法**（案例验证 6/6 全过）：生图要"一步到位带英文文案 + 左上角留空给 Logo"时，Prompt 必须显式包含：
  `NO text in the upper half of the image, the top-left 220x220 pixel area must be completely empty and clean with no text no objects no product parts, any short English copywriting text ONLY in the lower third of the image, no logo, no watermark`
  不得使用含糊的 `empty clean area at top left corner`——它与 copywriting 并存时 AI 会优先放文字到左上角。
- 每张Prompt只需包含：本图目的与画面方向、产品一致性要求、必要英文短文案、左上角Logo预留区、人物要求（如适用）、1:1比例，以及无Logo、无水印。
- 每张图统一为1:1写实商业图片；涉及人物时使用与场景匹配的成年欧洲白人模特。
- 每张图统一保留左上角固定150×180 px的Logo预留区，适用于不小于1024 px的方图和固定90×131 px Logo（左边距40 px、上边距30 px）。该区域使用连续干净背景，产品、人物、文字、图标、尺寸线、装饰及重要细节均不得进入；允许不影响Logo识别的轻微背景渐变或自然光影。
- Image 1–6均可使用必要、简短、自然的英文画面文案；**文案一律安排在画面下三分之一区域**；没有实际信息价值时不加文字。全部图片无Logo、无水印。
- 英文Prompt与对应中文保持逐项一致，但中文无需机械重复所有通用约束，也不得在前面添加中文标签。
- **Prompt 区块格式（与 b2b-image 生图脚本的硬性接口）**：方案中每个 Image 区块必须使用 `### Image N`（三级标题，不是 `####`），English Prompt 行使用 `**English Prompt:**` 加粗标记独占一行，下一行为 `**对应中文：**`。生图脚本按此格式解析；格式不符会解析不到 Prompt，或把中文误并入英文。

## 7. 生图验收（每次生成后必做）

- 6 张图生成完成后，逐张对照参考图验收四项：
  1. **产品形态一致**：画的是不是同一款产品（不是别的产品、不是相似品类替代物）；
  2. **颜色/材质/结构一致**：与参考图相符；
  3. **左上角安全区干净**：可用 ps-batch-image-actions 的安全区检查辅助；
  4. **文案位置与拼写**：在预期位置、无 AI 拼写硬伤。
- 任一图不达标：**只重做该张**，不整批重跑；在 `产品状态.md` 记录问题图、原因和重做结果。
- 安全区检查（边缘密度检测）只证明左上角无内容，**不验证产品形态**——产品形态必须人工/AI 对照参考图核验。

## 基础合规

- 未经证据支持，不声称认证、检测、环保、可回收、有机、食品级、医用级、专利、销量、工厂规模、交期或质保。
- 材质必须准确，例如不得把 TPE 写成天然橡胶；无证据不得使用 `Organic`、`Recycled`、`Biodegradable`。
- 不生成虚假认证标志、证书编号、绝对化承诺或无法验证的比较结论。
- 修改任何局部内容后，复查标题、关键词、卖点与六图策略的一致性。
