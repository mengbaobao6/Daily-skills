# 跨境电商产品营销方案生成器

分析产品链接、图片或基础资料，生成可用于阿里巴巴国际站的无品牌商业营销方案。

核心流程：

```text
产品分析
→ 采购人群分析
→ Commercial Strategy Engine
→ 3套 Buyer Persona 策略
→ 每套标题、关键词、卖点与第一张主图
→ 每套对应的后续5张图片
```

三套方案测试的是不同采购人群和商业定位，不是随意替换几个标题词或图片背景。标题、关键词、卖点、第一张主图及后续图片必须围绕同一策略保持一致。

---

## 全局规则

1. 删除来源页面中的品牌名、商标、Logo、平台名、版权角色、专利外观暗示及未经授权的对标品牌词，以“无品牌”方式呈现。
2. 不得把来源平台、销售渠道或客户类型写成产品品牌或产品属性，例如不得使用 `for Amazon Users`、`Amazon Style`、`Amazon Best Seller`。
3. 只把页面、图片或用户资料明确支持的信息写成事实。
4. 缺失信息可合理推断，但必须逐项标注 `【推断】`；不得把推断内容写成确定事实。
5. 认证、检测、环保、可回收、有机、食品级、医用级、专利、销量、工厂规模、交期及质保等主张必须有证据。无证据时不得生成认证标志、证书编号或确定性文案。
6. 产品材质必须准确。不得把 TPE 写成天然橡胶，也不得在没有认证或证据时使用 Organic、Recycled、Biodegradable 等词。
7. 英文输出必须自然、适合B2B采购场景；中文释义必须与英文内容逐项同步。
8. 三套策略可以共享真实产品信息，但必须通过不同的采购人群、搜索意图、价值主张和摄影语言形成可测差异。

---

## 工作流程

### 第一步：获取产品信息

1. 接收用户提供的产品链接、产品图片、规格表或基础信息。
2. 读取页面或资料，提取：
   - 产品标题与通用产品名称
   - 主图及外观
   - 价格区间
   - SKU规格，包括颜色、尺寸、款式
   - 材质与产品结构
   - 尺寸、重量、容量等参数
   - 功能、使用方式与适用场景
   - 包装、起批量及定制能力
   - 店铺与品牌信息，仅用于识别后删除
   - 月销量、主要销售地区及下游渠道，如有
3. 页面信息不完整时，搜索同类产品或竞品作为辅助判断。不得把竞品参数当作本产品事实。
4. 将信息分为：
   - `已确认`：来源页面、图片或用户资料明确支持。
   - `【推断】`：依据外观、类目或同类产品合理判断。
   - `待确认`：无法可靠判断且会影响标题、图片或合规性的字段。
5. 对关键待确认项优先向用户说明；若用户要求直接生成，则使用保守表达并标注 `【推断】`。

### 第二步：输出产品基本信息表

输出：

| 项目 | 内容 |
|------|------|
| 产品名称 | 多个无品牌通用同义词用 `/` 分隔 |
| 产品类目 | 使用 `>` 分层 |
| 材质 | 实际材质及证据状态 |
| 产品结构 | 结构描述 |
| 规格参数 | 尺寸、重量、容量等；推断项标注 `【推断】` |
| SKU类型 | 按颜色、尺寸、容量、款式等组合 |
| 当前价格 | 来源页面价格与币种 |
| 美金价格 | 注明采用的汇率与换算日期；不能联网时标注为估算 |
| 起批量 | 已知值或 `待确认` |
| 定制能力 | Logo、颜色、包装、结构等；无证据项标注 `待确认` |
| 预估产品定位 | 入门级、经济型、走量款、中端或高端；标注判断依据 |
| 证据缺口 | 可能影响合规或营销表达的待确认信息 |

表格中不得出现任何用于营销的品牌名称。

### 第三步：采购人群分析与 Commercial Strategy Engine

先识别可能购买该产品的B2B采购人群，再从中选择三个可区分、可执行、可测试的 Buyer Persona。

#### 3.1 候选采购人群

根据产品实际情况评估，不得机械套用固定三类。候选类型包括：

- Distributor / Wholesaler：经销商、批发商、进口商
- Brand Owner / Private Label Buyer：品牌商、私标客户
- Retail Chain / E-commerce Seller：零售连锁、电商卖家
- Gym / Studio / Club Buyer：健身房、工作室、俱乐部
- School / Institution / Project Buyer：学校、机构、项目采购
- Promotional Gift Buyer：礼赠品及活动采购
- Rental / Hospitality / Commercial Operator：租赁、酒店或商业运营方

#### 3.2 选择规则

Commercial Strategy Engine 必须：

1. 选择三个商业价值明确且彼此不同的采购人群。
2. 优先选择与产品用途、MOQ、定制能力、价格带及市场匹配的人群。
3. 不得仅把 `SEO`、`OEM`、`Premium` 当作采购人群；它们是策略手段或价值表达。
4. 若产品只适合一至两类采购人群，不得虚构第三类。第三套可改为同一人群下不同采购任务，例如补货走量、私标开发、项目采购。
5. 每套策略必须明确：
   - Buyer Persona
   - 采购任务与应用场景
   - 核心采购痛点
   - 购买决策因素
   - 搜索意图
   - 核心价值主张
   - 关键词簇
   - 首图第一印象
   - 后续图片叙事方向
   - 不应出现的内容

#### 3.3 输出格式

先输出选择摘要：

| 策略 | Buyer Persona | 采购任务 | 核心痛点 | 价值主张 | 搜索意图 | 选择理由 |
|------|---------------|----------|----------|----------|----------|----------|
| A | ... | ... | ... | ... | ... | ... |
| B | ... | ... | ... | ... | ... | ... |
| C | ... | ... | ... | ... | ... | ... |

然后为每套策略输出一张 Creative Direction Card：

```markdown
### Strategy A — [英文策略名] / [中文策略名]

- Buyer Persona:
- Procurement Mission:
- Primary Pain Points:
- Decision Drivers:
- Search Intent:
- Core Value Proposition:
- Keyword Cluster:
- Hero Image First Impression:
- Photography Language:
- Supporting Image Narrative:
- Avoid:
```

三套策略必须有清晰差异，但不能以牺牲产品真实性或首图识别度制造差异。

### 第四步：生成3套完整商业策略包

每套策略包必须包含：

1. 一个英文B2B标题
2. 五个后台关键词
3. 六条核心卖点
4. 第一张主图 Creative Direction
5. 后续五张图片的叙事规划

标题、关键词、卖点和图片方向必须共同服务于该 Buyer Persona。

#### 4.1 标题规则

- 长度按 Python `len(title)` 计算，包含字母、数字和空格，必须满足 `100 < 字符数 < 125`，即允许101至124个字符。
- 三个标题生成后必须使用 Python 逐一核验字符数。任何标题不在101至124字符范围内，都必须重写并再次运行核验，禁止仅凭人工估算字符数。
- 不使用逗号、感叹号或无必要标点。
- 核心产品词前置。
- 材质、规格、功能、场景及交易词只在真实且与策略相关时使用。
- B2B交易词可使用 `Wholesale`、`Bulk`、`Custom`、`OEM`、`ODM`、`Private Label`、`Supplier`、`Manufacturer`，但必须与已确认能力匹配。
- 不强制每个标题都加入 Factory、OEM 或 Wholesale。
- 不堆砌近义词，不使用与产品无关的高流量词。
- 不使用任何第三方品牌、平台商标或未经证实的认证词。
- 三个标题允许保留必要的核心产品词，但其余关键词应反映不同采购意图。

Python核验必须使用与以下逻辑等价的代码：

```python
titles = {
    "Strategy A": "替换为Strategy A英文标题",
    "Strategy B": "替换为Strategy B英文标题",
    "Strategy C": "替换为Strategy C英文标题",
}

all_valid = True

for strategy, title in titles.items():
    length = len(title)
    valid = 100 < length < 125
    all_valid = all_valid and valid
    print(f"{strategy}: {length} characters | {'PASS' if valid else 'FAIL'}")

if not all_valid:
    raise ValueError("All B2B titles must contain 101 to 124 characters.")
```

核验规则：

1. 将最终英文标题原样放入 Python 字符串，不得使用中文释义或删减后的版本代替。
2. `len(title)` 的结果是输出表格中的字符数，禁止手工填写其他数字。
3. 必须确认三个策略的标题均已获得 `PASS` 才能继续生成或交付完整方案。
4. 若某个标题出现 `FAIL`，只重写并重新核验当前失败标题；已经通过的标题保持不变，无需重复核验。
5. 交付结果时保留核验状态，但无需向用户展示Python源代码或终端过程，除非用户明确要求。

标题输出格式：

```markdown
#### B2B标题

| 项目 | 内容 |
|------|------|
| 英文标题 | ... |
| 字符数 | ...字符 |
| Python核验 | PASS |
| 中文释义 | ... |
| 关键词逻辑 | 说明该标题如何匹配本策略的采购搜索意图 |
```

#### 4.2 关键词规则

每套输出5个英文关键词：

- 至少2个高相关产品词或长尾产品词。
- 至少1个与采购任务相关的词。
- 至少1个能区分该策略的材质、功能、场景或交易意图词。
- 关键词必须可独立作为搜索短语使用。
- 不得包含品牌词、平台词、无证据认证词或与产品不符的材质词。
- 三套关键词可共享最核心产品词，但整体重叠率应尽量低。

输出格式：

```markdown
#### 5个关键词

1. ...
2. ...
3. ...
4. ...
5. ...
```

#### 4.3 六条核心卖点

每套生成6条与对应 Buyer Persona 一致的英文卖点及中文释义。

规则：

- 每条卖点单独成段，中间空一行。
- 每条是一句完整英文，不使用破折号拼接碎片。
- 体现“产品特性 + 采购利益”。
- 自然包含相关搜索词，不重复堆砌同一个完整核心词。
- 六条分别覆盖产品性能、规格或结构、使用价值、采购价值、定制或供应能力、风险降低或信任因素。
- 只有在资料支持时才能写确定的 MOQ、交期、认证、产能、质保及环保主张。
- 三套卖点不是同一组文案简单换序；重点必须对应各自采购人群。

输出格式：

```markdown
#### 英文卖点

1: ...

2: ...

3: ...

4: ...

5: ...

6: ...

#### 中文释义

1: ...

2: ...

3: ...

4: ...

5: ...

6: ...
```

#### 4.4 策略包输出顺序

按以下顺序完整输出 A、B、C，不得先输出三个标题再单独输出图片：

```text
Strategy A
→ 标题
→ 关键词
→ 卖点
→ 6图规划

Strategy B
→ 标题
→ 关键词
→ 卖点
→ 6图规划

Strategy C
→ 标题
→ 关键词
→ 卖点
→ 6图规划
```

### 第五步：为每套策略生成6张AI图像Prompt

每套策略都生成 Image 1 至 Image 6，共3套。Image 1 是可直接作为阿里国际站第一张主图的 Hero Image；Image 2 至 Image 6 延续同一商业策略。

#### 5.1 第一张主图的绝对约束

三套策略的 Image 1 都必须遵守：

- 完整展示产品主体，任何关键部位不得裁切出画面。
- 第一眼必须准确识别“卖的是什么”。
- 产品为唯一或绝对主要视觉主体，占画面约75%至85%。
- 使用白色或非常浅的中性背景，保持搜索结果页识别度。
- 不使用人物、工厂、仓库、证书、包装堆、信息图拼贴或局部特写作为首图主体。
- 不用夸张道具、复杂生活场景或装饰遮挡产品。
- 只通过摆放方式、机位、布光、阴影、背景色温和材质表现改变摄影语言。
- 允许展开、卷起、折叠或组合摆放，但必须符合产品真实形态，且至少有一个完整产品清晰可见。
- 不虚构附件、结构、纹理、Logo、颜色或包装。
- 默认不添加文字，优先输出干净的无字首图。若用户明确要求首图文字，仅允许一个简短无品牌产品名称，不得加入卖点、徽章或促销文案。

#### 5.2 三套首图如何形成差异

差异必须来自 Commercial Strategy Engine，而不是把首图变成详情图。可采用：

| 首图语言 | 可用方式 | 禁止方式 |
|----------|----------|----------|
| 清晰目录型 | 纯白底、标准45度、完整产品、明确轮廓 | 文字堆叠、复杂场景 |
| 专业规格型 | 完整产品组合摆放、展示真实厚度或结构、理性布光 | 尺寸线、剖面放大窗、工厂图占主画面 |
| 高价值品牌型 | 完整产品、浅中性背景、柔和高级布光、克制阴影 | 只拍纹理、人物生活方式照、奢华道具遮挡 |

上述三种不是固定分配。应根据三个 Buyer Persona 的决策因素选择适合的摄影语言，并在 Creative Direction 中说明理由。

#### 5.3 后续五张图片

Image 2 至 Image 6 的角色可根据策略调整，不得机械复制同一套顺序。每套应从以下内容中选择并排序：

- 核心功能与利益
- 材质、结构或工艺
- 尺寸、规格及SKU
- 使用场景
- 定制选项与私标能力
- 包装与交付
- 商业使用或项目适配
- 质量控制与真实认证
- 对比与选型
- 采购信任与服务

约束：

1. 后续图片必须回答该 Buyer Persona 的真实采购问题。
2. Strategy A、B、C 可有不同的图片角色和排序。
3. 同一策略内保持相同的产品颜色、结构、材质、灯光基调、排版系统和文案语气。
4. 不得出现“首图高端、后图突然工厂批发风”或“首图专业采购、后图全部消费级生活方式”的割裂。
5. 工厂、仓库、证书和检测场景只能在有真实资料或参考图时生成；没有证据时改为中性的质量检查、包装选项或服务流程表达，并标注需要素材。
6. 应用场景中的模特应依据目标市场和产品实际用户选择，不得默认限定某一族裔。只有用户明确指定时才执行特定外貌要求。

#### 5.4 每套图片规划表

在撰写Prompt前先输出：

| 图片 | 图片角色 | 采购问题 | 核心信息 | 视觉方向 | 与策略的关系 |
|------|----------|----------|----------|----------|--------------|
| Image 1 | Hero Image | 这是什么产品 | ... | ... | ... |
| Image 2 | ... | ... | ... | ... | ... |
| Image 3 | ... | ... | ... | ... | ... |
| Image 4 | ... | ... | ... | ... | ... |
| Image 5 | ... | ... | ... | ... | ... |
| Image 6 | ... | ... | ... | ... | ... |

#### 5.5 每张图的输出格式

```markdown
### Strategy [A/B/C] Image [编号] — [图片名称]

**Purpose:**
[该图服务的采购问题和转化目标]

**English Prompt:**
[详细英文Prompt]

**中文释义：**
[与英文Prompt完全对应的中文说明]
```

#### 5.6 Prompt编写规则

1. 产品颜色、材质、结构和外观必须与实物一致。
2. 在相关图片中嵌入真实规格；不确定项不得伪装成精确参数。
3. Image 1 使用干净首图规则；Image 2 至 Image 6 才可使用信息图、尺寸线、功能标注、场景、包装或信任元素。
4. 文字必须是英文，简短、可读、无品牌，不得使用未经证实的认证或绝对化承诺。
5. 不使用引号包裹图片中的文字标签。
6. 默认使用1:1比例、写实商业摄影、高细节和清晰产品边缘。
7. 除非图片本身需要场景，优先使用白色或浅中性背景。
8. 每张图均使用左上角18%×18%强制Logo禁入区。以下布局块原样放在每张英文Prompt最前面，且优先级高于产品、场景和文案要求：

   ```text
   MANDATORY LOGO EXCLUSION ZONE — HIGHEST PRIORITY:
   Reserve the upper-left rectangle covering x=0 to 18 percent and y=0 to 18 percent of the canvas as a completely empty logo-safe exclusion zone.
   This rectangle must contain only clean continuous background.
   No text, letter, number, icon, product, packaging, model, hand, prop, dimension line, copywriting decoration, shadow, outline, or important visual detail may enter, overlap, or touch this rectangle.
   All copywriting may be placed freely anywhere outside this exclusion zone according to the best visual composition.
   Do not force copywriting into the upper-right corner; only keep it outside the exclusion zone with clear spacing from the boundary.
   ```

9. 在每张英文Prompt尾部、统一英文限定之前原样追加：

   ```text
   FINAL LAYOUT CHECK: Keep the entire upper-left 18 percent by 18 percent exclusion zone completely empty. Keep every part of all copywriting, outlines, shadows, products, and important details outside this zone.
   ```

10. 中文释义同步说明：左上角画布 `x=0–18%`、`y=0–18%` 为强制Logo禁入区，只保留连续干净背景；文字可以根据构图自由放在其他位置，但文字本体、描边、阴影、装饰、产品和重要元素均不得进入、接触或覆盖禁入区，并与边界保持明显间距。如果有场景图，禁入区之外正常保留场景。
11. Image 1 的英文Prompt尾部追加：

   ```text
   No text no logo no watermark Ratio 1:1
   ```

### Logo禁入区输出自检

- 每个英文Prompt必须同时包含开头的 `MANDATORY LOGO EXCLUSION ZONE` 和尾部的 `FINAL LAYOUT CHECK`。
- 只限制左上18%×18%禁入区，不得把所有图片的文字机械地固定在右上角。
- 如需展示定制Logo能力，把可定制位置放在产品或包装上，不得要求在左上禁入区放示例Logo。
- 禁止同时出现“禁入区保持空白”和“禁入区放示例Logo”等冲突要求。
- 方案生成完成后逐图检查上述规则，缺失或冲突时先修正Prompt，再进入生图。

## 迭代优化原则

| 用户反馈 | 应对方针 |
|----------|----------|
| 中文释义没同步 | 同时更新英文与中文，逐项核对 |
| 改标题 | 同步检查关键词、卖点及图片策略是否仍一致 |
| 改采购人群 | 重新运行 Commercial Strategy Engine，并重做该策略包 |
| 加规格参数 | 只嵌入真实或明确标注为推断的规格 |
| 删除品牌 | 清查标题、关键词、卖点、图片文字、包装及Prompt中的品牌信息 |
| 首图不像主图 | 强制恢复完整产品、浅色背景、75%至85%产品占比及无详情元素 |
| 图片风格割裂 | 按 Creative Direction Card 统一灯光、配色、排版、文案语气与采购叙事 |
| 加Logo避让 | 每张Prompt开头加入18%×18%左上强制禁入区，尾部加入 `FINAL LAYOUT CHECK`；只限制左上禁入区，不限制文字在其余区域的位置，并同步中文 |
| 工厂或认证不真实 | 删除虚构元素，改为待补素材或中性质量流程表达 |
| 每行换行 | 卖点之间保留空行 |

任何局部修改都必须检查整套策略的一致性，不能只改标题或单张图片而不更新其关联内容。
